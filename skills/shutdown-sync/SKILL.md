# 收工與同步

先讀 [共用接續協定](../startup-sync/references/workflow.md)，依最近專案規則及使用者授權執行。收工不繼續展開未授權的新工作，不預設可以公開、提交或推送。

1. 對照工作中已保存的現況、事件及本輪對話／檔案差異。列完成、未完成、使用者決策、驗證與缺口；對話已壓縮時以落盤證據恢復，缺失不得猜補。
2. 更新單一現行區與唯一下一步；已失效的任務退出活躍入口。完整原稿／原始資料保留原處，交接以連結與必要證據定位，不在多份入口複製。
3. 同根因沿既有 ID；同一次失誤的澄清去重，獨立交付再犯另記。已能核定的事件當次結算，不能永遠留「舊總數＋待結算」。未確定者保留待判，不能湊數。
4. **同專案累計 3 次升專案重要規則，5 次升全域；累計不歸零。**已有相同全域規則就合併。新權威與事件先寫入、讀回，再清除原活躍重複；專案保留全域 ID、必要差異與證據回鏈。既有已升全域規則不倒退降級。
5. 通用回饋寫入 vault 原卡；本專案事件留工作筆記／交接，來源狀態留來源索引或工作表。知識庫 index／log、每日筆記只補必要回鏈，不複製全文；Clippings 不動。
6. 檢查檔案命名、原始資料保護、保密及授權刪除紀錄。Hook／腳本失敗與未完成內容實測須保留，不能只報驗證數量。
7. 讀回現況、規則、事件與回鏈，執行檢查器；重跑收工不可新增相同事件或重複待辦。工程檢查不能替代主線、來源及指定交付的語義驗收。
8. Git 只處理已授權的目標倉庫／檔案。只有使用者明確要求或專案既有授權涵蓋時，才 stage 指定檔案、commit、push；禁止 `git add .`。不發布私人原稿、憑證或無關未追蹤資料。使用者要求更新 skills 時，接續 skills-sync 完成其備份、套件、GitHub 與筆記。
9. 分開回報已保存、已修正、已測試、已提交／推送與未驗證項。Drive 本機檔案存在不等於跨裝置同步完成；Hook 已配置不等於已信任／已觸發。

權限或遠端失敗只阻擋相依項；完成其他工作並精確報告。沒有變更就不製造提交或新日誌。使用者要求換電腦時，交接必須包含可由固定入口恢復的未完工作。
