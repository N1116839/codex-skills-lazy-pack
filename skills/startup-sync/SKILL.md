# 開工與工作中接續

先讀 [共用接續協定](references/workflow.md)。開工恢復、工作中保存、收工整理；使用者已指定下一步就繼續，不因技能要求再次確認已知方向。

1. 確認 cwd、最近 AGENTS／README 與 Git 根目錄。讀指定 vault 的 AGENTS／CLAUDE、專案索引、相關現行全域規則及本專案總覽／工作筆記／來源索引。優先使用設定路徑；此環境既定 vault 為 `G:\我的雲端硬碟\我的第二大腦`。
2. 以單一現行區恢復主線、當前任務、底稿、最新更正及未完成事項。遇多個「最新」先比對替代關係，不依日期段落或搜尋命中擅選舊下一步。歷史只在有疑義或證據需求時展開；來源索引不是原典驗證。
3. 有 `.project-workflow.json` 時執行 `python <本技能>/scripts/project_workflow.py context --project <cwd>`。來源缺失、重複標記或超出容量時先修正，不默默截斷或假稱已讀。未初始化時可依既有入口人工恢復，明示自動恢復尚未驗證。
4. 每個適用踩坑以 ID 對照觸發、實際檢查、停止條件及回寫位置；核對同專案事件累計與 3／5 層級。只在觸發的任務套用，不把所有歷史塞進每輪。
5. Git 狀態限本專案檢查，再簡述外層相關狀態；只有需要核遠端才 fetch，不自動 pull、stage、commit 或 push。
6. 開工回報精簡列上次進度、下一步、已查／未查、適用防錯及未同步狀態。開工本身不新增日誌或重寫底稿；有新的使用者決策或糾正則立即更新現行區，不能拖到收工。

工作中遇目標改動、指定原稿、方案接受、糾正或完成子工作，更新同一現行區並留必要證據。每次實質交付前重新核對指定範圍、底稿、證據及實際結果。若 Hook 提供 session／turn，按協定取得最新 context，再記 checkpoint；`unchanged` 也必須說明本輪核對，不能只為通過檢查而點名「已讀」。

正常對話不貼整張現況、不按每則訊息新增踩坑。不確定是否發生壓縮也採相同恢復步驟，不憑模糊記憶重新選路。工具接續與語義驗收分開回報。
