# 開工與工作中接續

先讀 [共用接續協定](references/workflow.md)。開工恢復、工作中保存、收工整理；使用者已指定下一步就繼續，不因技能要求再次確認已知方向。

1. 確認 cwd、最近 AGENTS／README 與 Git 根目錄。讀指定 vault 的 AGENTS／CLAUDE、專案索引、相關現行全域規則及本專案總覽／工作筆記／來源索引。優先使用設定路徑；此環境既定 vault 為 `G:\我的雲端硬碟\我的第二大腦`。
2. 以單一現行區恢復主線、當前任務、底稿、最新更正及未完成事項。遇多個「最新」先比對替代關係，不依日期段落或搜尋命中擅選舊下一步。用索引找到本輪所需的最新原件並讀足相關範圍，核對版本、存檔及取代關係。現況或摘要負責定位，原件負責查證。
3. 有 `.project-workflow.json` 時執行 `python <本技能>/scripts/project_workflow.py context --project <cwd>`。整包超限時用 `inspect --project <cwd>` 找出過長區段，再用 `context --project <cwd> --section <id>` 分批讀現況及任務必需規則。標記或路徑有誤則回查權威檔案；分批或人工讀取須如實回報核對範圍。
4. 先讀同一規則 ID 的最新有效版，按觸發、檢查、停止條件及回寫位置套用。依專案、任務及規則 ID 從事件帳或封存回鏈找到同類錯例，核對其原因與修正；計數按事件帳的 3／5 層級。個案證據與舊判斷保留供查，不把歷史待辦當現行指令。
5. Git 狀態限本專案檢查，再簡述外層相關狀態；只有需要核遠端才 fetch，不自動 pull、stage、commit 或 push。
6. 開工簡報上次進度、下一步、已讀的原件版本與適用踩坑。仍缺哪項原件或案例便明示範圍；只有載入現況或看到索引時，不稱完成本輪核讀。開工本身不新增日誌或重寫底稿；有新的使用者決策或糾正則立即更新現行區，不能拖到收工。

工作中遇目標改動、指定原稿、方案接受、糾正或完成子工作，更新同一現行區並留必要證據。每次實質交付前重新核對指定範圍、底稿、證據及實際結果。若 Hook 提供 session／turn，按協定取得最新 context，再記 checkpoint；`unchanged` 也必須說明本輪核對，不能只為通過檢查而點名「已讀」。

跨 AI 接手也從同一份專案現況、規則、事件帳與封存回鏈開始；依主機可用能力手動讀或執行檢查器，Hook 與上個 AI 的對話不是必要條件。

正常對話不貼整張現況、不按每則訊息新增踩坑。不確定是否發生壓縮也採相同恢復步驟，不憑模糊記憶重新選路。工具接續與語義驗收分開回報。
